# ShiftPad v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows Flutter app that reads a pair of Zwift Click V2 controllers over BLE and sends virtual-shift (and other) commands to MyWhoosh running on the same PC, via OpenBikeControl with a keyboard fallback, with no command limit.

**Architecture:** Pure-Dart core (Click V2 frame parsing, session state machine, keymap, output routing) behind small interfaces (`BleLink`, `GameOutput`, `KeyInjector`, `MdnsAdvertiser`) so it is unit-tested with fakes. Windows specifics (BLE via `universal_ble`, key injection via `win32` `SendInput`, mDNS via `dnsapi.dll` `DnsServiceRegister` through `dart:ffi`) sit behind those interfaces; other platforms get stubs for now. Two hardware checkpoints with the owner on the bike validate the protocol assumptions the spec marks "à vérifier".

**Tech Stack:** Flutter (latest stable) / Dart 3, `universal_ble`, `win32`, `ffi`, `shared_preferences`, `path_provider`, `flutter_localizations` + `intl` (gen-l10n), dev: `fake_async`.

**Spec:** `docs/superpowers/specs/2026-10-19-shiftpad-design.md` (French). Read it before Task 1.

## Global Constraints

- **Execution happens on the bike PC** (Windows, MyWhoosh installed, D500 + both Click V2 in BLE range). Checkpoint tasks need the owner present to press buttons/ride; ask them in plain simple French, one instruction at a time.
- Product name **ShiftPad**. Never "MyShift", "Zwift" or "Whoosh" in the product name, window title or package id. Package: `shiftpad`, org `app.shiftpad`.
- **Do not copy code from github.com/OpenBikeControl/bikecontrol** (non-commercial license) or any GPL project (old BikeControl ≤ tag `gpl3`, qdomyos-zwift). Protocol facts only. MIT sources (zwiftboard, ClickShift, ZwiftClickV2-Bridge, openbikecontrol-protocol) may be consulted; if code is adapted, credit it in `THIRD_PARTY_NOTICES.md`.
- **Never call Zwift servers.** No Zwift account/OAuth anywhere in the app. No "emulate a Click towards the Zwift app" relay in v1.
- No payment, licensing, trial or command counter in v1.
- UI copy: **simple English**, all strings in `lib/l10n/app_en.arb` (no hardcoded user-facing strings in widgets).
- Windows is the only shipped platform in v1; Android/macOS/iOS folders exist and compile with stub implementations of platform interfaces.
- BLE (from spec §5.1): manufacturer ID `0x094A`; side byte `0x0A` = right, `0x0B` = left; service `00000001-19CA-4651-86E5-FA29DCDD09D1` (alt service `0000fc82-0000-1000-8000-00805f9b34fb`); chars Async `00000002-19CA-4651-86E5-FA29DCDD09D1` (notify), SyncRx `00000003-19CA-4651-86E5-FA29DCDD09D1` (write w/o response), SyncTx `00000004-19CA-4651-86E5-FA29DCDD09D1` (indicate).
- Button masks (active-low, bit 0 = pressed): LEFT `0x1`, UP `0x2`, RIGHT `0x4`, DOWN `0x8`, A `0x10`, B `0x20`, Y `0x40`, Z `0x80`, MINUS `0x100`, PLUS `0x1000`. Buttons opcode `0x23`.
- Target latency: < 100 ms from BLE notification received to output sent (logged per event).

## Review Focus

1. **Rapid repeated shifting** (owner hammers + ten times in two seconds, or both pods pressed at once): every press must produce exactly one shift, in order, none dropped or doubled → test in Task 3 (`ButtonDiffer`) and Task 10 (`ShiftPadController`).
2. **Left pod locks mid-ride** (challenge frame arrives, or left was never unlocked): app must switch to the right-only keymap automatically and say so, not silently lose "−" → test in Task 4 (lock detection) and Task 10 (fallback).
3. **Pod already held by Zwift / Companion** (connect fails or no notifications): status must show "used by another app", retry later, never crash → test in Task 4 and Task 5.
4. **MyWhoosh closes or the OpenBikeControl TCP client drops mid-ride**: router must fall back to keyboard (or "none") within one event and recover when MyWhoosh reconnects → test in Task 9.
5. **Garbage / truncated / unknown frames after a Zwift firmware update**: parser never throws; frame is logged as unknown → test in Task 2.
